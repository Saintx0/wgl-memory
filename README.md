# 罔两 · 记忆（WGL Memory）

配合「罔两」Chat Completion 预设使用的轻量记忆扩展。
**零模型调用、零向量库、零外部存储**——记忆来源是预设本来就在输出的 `<scene>` / `<state>`。

## 它和「柏宝书」的关系

柏宝书是完整的记忆引擎（自动摘要 + 多层总结 + 物品/人物/悬念台账 + 向量召回 + 副 API）。
本扩展只借它的**四个原理**，其余全部用别的方式换掉：

| 柏宝书的能力 | 它在背后靠什么 | 本扩展怎么拿到 |
|---|---|---|
| 自动摘要 | 每轮一次 LLM 调用 | `<scene>` 行本身就是一行结构化摘要。**白拿** |
| 多层总结 | LLM 再压缩一层 | **机械分层**：近 N 轮逐条，更早的按「地点」合并成时间块 |
| 时间线锚点 | LLM 给每楼打故事内时间 | `<scene>` 第 2 段就是时间。**白拿** |
| 物品 / 穿着台账 | LLM 提取 | `<scene>` 第 4 段写的是「衣物到哪一步、东西在谁手里」。**白拿** |
| 悬念簿 | LLM 提取 | `<state>` 第 4 个字段 `钩=`，每轮多写 10 个字 |
| NPC 名册 / 好感 / 了解清单 | LLM 提取 + 独立台账 | **手填**「固定设定」+ 预设自带的认知边界规则 |
| 向量记忆 | embedding + 每轮 query 重写（又一个 LLM） | **不做** |
| 隐藏旧楼层省 token | 自己接管上下文发送 | **不做**，交给 SillyTavern 自己的裁剪 |
| 换对话带记忆 | 打包迁移 | **导出 / 导入 JSON** |

一句话：**柏宝书是「生成记忆」，本扩展是「回收记忆」。**
前者必须每轮调模型，后者零成本——因为罔两预设已经把记忆写出来了。

## 另一个关键差别：无状态

本扩展**不存储任何东西**（除了你手填的固定设定）。
每次生成前，它把整段聊天重新扫一遍，重新抽 `<scene>` / `<state>`。

好处：

- 打开一个**旧聊天**，立刻就有记忆——不需要从第一轮就装着它
- 删楼、编辑、swipe，记忆自动跟着变，不会错位
- 没有增量状态可以腐坏

代价：每次生成多扫一遍消息数组，几十毫秒，可以忽略。

## 注入结构

放在倒数第 2 条之前（可调），内容长这样：

```
【设定·手动】
林晚，27，旧书店店主。目标：把店盘下来。

【设定·已确立】（按轮次，同一件事以最早的为准）
第1轮｜她的小指是小时候骨折留下的

【在场名册】（数字＝出现轮次；只出现一次的算过场，不要再让他开口）
我（18）、林晚（18）、卷帘门师傅（1·过场）

【地点】（按出现次数）
旧书店柜台后（12）、后间（4）

【当前·最近 6 轮】
第12轮｜旧书店柜台后｜傍晚将暗｜我、她｜她趴在柜台上；基线=嘴硬；紧度=紧
第13轮｜旧书店后间｜夜里十一点｜我、她｜她背对着我把衬衫扣子系回去；基线=在装没事；紧度=松

【远史·按地点合并】
第3–7轮｜旧书店｜傍晚 → 夜里｜结束于：她把卷帘门拉到一半
第8–11轮｜后间｜夜｜结束于：她蹲在地上捡书

【未办的事】
· 她说过九点要给人回电话
· 柜子最下面那层她一直挡着不让看

【当前故事时间】夜里十一点

以上是已经发生过的事，续写必须与之一致：
· 时间、地点、在场的人不许推翻；走了的人不许凭空回来。
· 已经发生过的步骤不再重演，从上一条的落点往下接。
· 不许引入上面没出现过的人，不许另起一条线。
```

末尾三条和预设的【不许添加】是同一个意思，但放在记忆块里，紧贴事实清单，约束力更强。

## 安装（TauriTavern）

Tauri 打包版的用户数据不在安装目录，而在 `%APPDATA%`：

```
%APPDATA%\com.tauritavern.client\data\extensions\third-party\wgl-memory\
    index.js
    manifest.json
    style.css
```

原版 SillyTavern 则是 `SillyTavern/public/scripts/extensions/third-party/wgl-memory/`。
两处目录结构一致，文件可以直接搬。

装完刷新，扩展设置里出现「罔两 · 记忆」。
**先填「固定设定」**——这一步比任何参数都管用，然后点「预览」确认抓到了东西。

## 三层记忆，可靠性从高到低

| 层 | 来源 | 可靠性 | 内容 |
|---|---|---|---|
| **机械层** | 从 `<scene>` 统计 | 100% | 在场名册（谁出现过几次、谁是过场）、地点频次、时间跨度 |
| **半自动层** | 模型输出的 `<fact>` 行 | 不稳（实测 3 轮出 1 条） | 来历、过去、身体、长期目标 |
| **手动层** | 面板输入 | 100% | 你自己写死的设定，权重最高 |

> **能让机器算出来的，不要指望模型。**
> 「谁在场、谁只是路过」这种信息从 `<scene>` 数一遍就有，比让模型总结可靠得多。
> `<fact>` 只作为补充——它出得来最好，出不来也不影响主干。

## 事实为什么不「变动」只「追加」

让模型每轮重写事实清单，会**改写出它没资格改的东西**。
实测过：把锚点写进状态行之后，模型把「生下来就有，米粒大」改成了「摔的」「磕的」——摘要变成了它自己的创作。

所以规则是 **append-only + 最早优先**：
- 模型只能新增 `<fact>`，不能改旧的
- 插件按轮次列出，注入时写明「同一件事以最早的为准」
- 要改，由你在面板里改（手动层）

## 设置项

| 项 | 默认 | 说明 |
|---|---|---|
| 启用 | 开 | |
| 注入深度 | 2 | 放在倒数第 2 条消息之前 |
| 逐条保留轮数 | 6 | 超过的部分进「远史」 |
| 扫描轮数上限 | 80 | 再往前的不看 |
| 固定设定 | 空 | 人名、关系、长期目标、不变的身体特征 |

## 建议的配合方式

- **固定设定写「不变的」**：姓名、年龄、关系、身体特征、长期目标。写在预设里会挤占注意力，写在这里权重更高且不占预设体积。
- **「钩」只在需要时写**：`<state>` 的 `钩=` 让模型每轮留一句未办的事，插件会把最近几轮的钩聚成「未办的事」。如果觉得模型写得太碎，可以在预设里把 `钩` 改成两轮写一次。
- **不要同时开柏宝书**：两个记忆系统会互相打架，注入两套事实清单，模型会选错。

## 注入的两条路

Tauri 打包版可能改变模块的 web root，所以代码不写死静态 import：

1. **优先 `setExtensionPrompt`**（标准做法），按 `../../../extensions.js` → `/scripts/extensions.js` → `./extensions.js` 依次尝试；
2. 全部失败就**退回 manifest 的 `generate_interceptor`**，直接往待发送的消息数组里插一条 system。

两条路都失败时控制台会有 `[罔两·记忆]` 开头的报错，把它贴出来即可定位。

## 已知限制

- 依赖 `<scene>` / `<state>` 标签。没有就退化成「截取正文前 36 字」，能用但很粗。
- 不做语义检索：远处某个细节只能靠「远史」那 8 行粗粒度线索，找不回原句。
- `setExtensionPrompt` 与 `event_types` 的签名随酒馆版本变过。报错请贴控制台。
- **别和柏宝书同时开**：两个记忆系统会各注入一套事实清单，模型会选错。
